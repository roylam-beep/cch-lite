把一串雜亂的工作一口氣做完。$ARGUMENTS

價值在三件事：同一個原因造成的問題放同一批、一次修到根；彼此無關的同時做；commit 前一定有不是作者的人審過。

## 什麼時候跑

使用者打 `/cc-batch`，或說「哪些有關連、可一併處理」「分批一起做」「開子 agent 批 1、2、3 併行」。
清單只有一件，或每件都要改同一批檔 → 不用這支，直接做。要開分支、開 PR、派 cloud agent → `/rr-dispatcher:cc-dispatch`。

## 步驟（照順序，不跳）

1. **收清單、逐條核對。** 來源照 `$ARGUMENTS`；留空用本對話最近一串待做事項。
   每條對檔案或指令確認問題還在（附 `檔案:行號`）；已經不在的劃掉並說明。
2. **按根因分組。** 照 `/cc-root` 第 2 步「找同根症狀」的問法：每條往上問「為什麼會這樣」，指到同一個上游的歸同一組。
   看起來同類但上游不同，不硬併。**改到的檔不重疊，不等於同一個原因。**
3. **切批。**
   - 同一組放同一批；每批列「只准改的檔」。
   - 兩批要改同一個檔 → 併成一批，或把後做的排到下一波。不准兩個子 agent 同時改同一個檔。
   - 共用檔（待辦清單、版號、交接單、CHANGELOG 這類人人都要動的）不分給任何一批，留給主 session。
   - 要使用者先拍板的條目（設計取捨、不可逆、花錢）單獨列「待拍板」，不派。
   - 每批附規模（session 輪數）。
4. **給使用者看分批，等一句點頭。** 一批一段：條目、根因一句、只准改的檔。
   這是整支唯一要問的地方；使用者同一句話已經說「直接做」就不問。
5. **同時派。** 同一則訊息每批開一個 Agent，`run_in_background: true`；`model` 照使用者點名，沒點名用 `"sonnet"`。
   每段 prompt 逐字包含：

   ```
   在 <repo 絕對路徑> 做「<批名>」。另有其他 agent 同時在同一個資料夾改別的檔，所以：
   只准改下面「你的檔」；不准 commit、git add、push、切分支；不准動 <共用檔清單>。
   你的檔：<清單>
   要做的事：<每條原文＋位置＋改成什麼>
   每個行為修正補測試，照 repo 現有測試的寫法。
   收尾：跑 <repo 的測試指令>；紅在你沒動的檔就照實記下，不要修。
   回報：改了哪些檔各一句、git diff --stat（只看你的檔）、測試結果、沒做或不確定的。
   ```

   派完照常回報，不等。
6. **收。** 全部回來後讀每份回報與 `git diff`；主 session 改共用檔（劃掉做完的待辦、升版號、更新交接單）；跑整套測試。
   紅了先判斷是不是預期的紅（例：改了要重新安裝才會一致的檔）——是就寫明，不是就修。
7. **審查，不能跳。** 叫 `/code-review`。找到的照修，修完重跑受影響的測試，逐條回報處理結果（修了／不用修／先不修＋原因）。
8. **每批各一個 commit，不 push。** 先 `git status`，只 stage 該批的檔；共用檔最後單獨一個 commit。
   commit 訊息寫：做了哪幾條、驗證跑了什麼、哪些沒驗。

## 踩過的坑

- `測試 | tail -1 && git add …` 的結束碼是 `tail` 的：測試紅了照樣往下跑。要判結果就別接管線。
- 子 agent 說「紅的不是我造成的」，主 session 要自己複查，不能直接信。
- 共用檔有格式上限（條數、每行字數）的，寫完先跑 repo 的文件檢查再 commit。
- 審查的修正動到另一批的檔，commit 時那個檔歸修正後的那批，訊息裡點名。

## 約束

- 只作用於當前 repo；跨 repo 的清單每個 repo 各跑一次。
- 不 push、不開 PR、不切分支；push 照使用者當輪授權另外問。
- 子 agent 的回報是線索不是證據：commit 前主 session 自己看過 diff、跑過測試。
- 分界：只追一個問題的根因用 `/cc-root`；做完驗有沒有照要求做到用 `/cc-gate`；開 PR 派工用 `/rr-dispatcher:cc-dispatch`。

## 回報

第 4 步：分批表。結束時：每批改了什麼、審查找到幾條修了幾條、測試結果（含預期的紅）、commit 清單、剩下沒做的條目與原因。

## 防什麼

一串雜事被臨場拼著做：同一個原因被拆到不同批修不到根、兩個子 agent 改到同一個檔互相蓋掉、做完沒人審就 commit。
也防：把「改到的檔不重疊」當成「同一個原因」來分組。
